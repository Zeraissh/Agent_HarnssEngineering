## 无障碍专项实测（AC-05/AC-06，浏览器真机走查）

走查方式：真实浏览器加载运行中的页面，枚举 Tab 序、实测 `:focus-visible` 计算样式、
检查 ARIA 结构与 aria-live 播报、用真实 keydown 验证标签组键盘模式。

**实测通过**：Tab 序完整（10 个交互元素全可达、无焦点陷阱）；焦点可见性
（`solid 2px #0969da`）；`<label for="task-input">` 关联生效；aria-live 播报
"新任务已提交：…"。

**实测发现并修复的两处 ARIA 结构缺陷**（静态断言无法发现，只有真实 DOM 才暴露）：

1. **孤儿 `role="option"`**：运行项带 `role=option` + `aria-selected`，但父容器
   `#run-list` 没有 `role="listbox"`。ARIA 规范要求 option 必须在 listbox 内，
   否则屏幕阅读器无法播报"第 N 项 / 共 M 项"。→ 已补 `role="listbox"` + `aria-label`。
2. **tab 三件套不全**：有 `role=tablist`/`role=tab`，但没有 `role="tabpanel"`，
   tab 也没有 `aria-controls`——辅助技术不知道标签控制哪个面板。→ 已补
   `aria-controls` + tab 稳定 id + 面板 `role=tabpanel`/`aria-labelledby`。
   同时改为 APG roving tabindex（未选中项 `tabindex=-1`）并**配套实现
   ←/→/↑/↓/Home/End 方向键切换 + 切换后焦点跟随**——只加 roving 不加方向键
   会让未选中标签彻底键盘不可达，比改之前更糟。

三条对应回归测试已入库（32a/32b/32c），其中 32c 专门锁死"roving tabindex
必须配方向键"这一对约束，防止后续改动只做一半。

## 附带修复的 harness 缺陷

s3c 期间从 verifier 日志中定位到一处 harness 自身缺陷并修复（不属报告范围，
但影响本轮核查质量）：`isReadOnlyCommand` 的只读命令白名单按 `|` 切段时不感知
引号，导致 `grep -n "a\|b" f` 这类带交替的合法只读命令被误判为管道链而拒绝；
verifier 因此反复退化重试、烧光核查轮次（s3b/s3c 连续两轮 fail-closed 空转的
元凶之一）。已改为引号感知扫描：引号内的 `|`/转义 `\|` 视作字面量，引号外的
重定向/链式/命令替换照旧拦截，未闭合引号按可疑拒绝。
