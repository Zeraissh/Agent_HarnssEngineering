## 1. 背景与总体结论

案例 #7 交付的 Web 宿主经 s3a–s3e 五轮整改，已把委托方整改报告 V1.0 全部条目关闭，
并建立了 axe-core 六画面常驻门禁。但那五轮全部是**在既有形态上打补丁**：详情页仍是
"带三个标签的日志容器"，服务端仍是"事件水管 + 浏览器当状态权威"。

v2 的动因不是审美，而是三类**补丁修不到**的结构性问题：

- **正确性**：存在会让运行永久挂死的状态机缺陷；审批审计记录在刷新后失真；
  六种终止原因被压成两种，其中两种恰是"核查救不了"的类型却显示为绿色成功。
- **交互层**：s3d 的键盘走查与 s3e 的 axe 门禁分别覆盖 Tab 序与静态 ARIA 结构，
  **两者都不覆盖"直播重渲染下焦点与输入的存活"**——实测焦点每 3 秒被摧毁一次，
  拒绝理由输入框在直播中不可用。
- **数据面**：宿主没有把 harness 已经产出的关键数据传给前端，其中
  `verify` 三件套的缺失使 **Web 路径上的 verifier 实际处于"无白名单"状态**——
  即案例 #4 那个 22 轮空转的核查饥饿配置。

**建议决策**：按「正确性 → 数据面 → 渲染机制 → 信息架构 → 视觉语言」顺序实施。
V-01~V-05 为发布阻断项，在其关闭前不建议把本宿主用于任何真实长任务。

## 2. 问题分级与整改目标

### P0 — 发布阻断

| 编号 | 已确认现象 | 证据 | 风险 | 整改目标 |
|---|---|---|---|---|
| **V-01** | **返工轮审批永久挂死**。`runVerified` 的 `drain` 无条件转发主轮 `done`（`src/orchestrate.ts:118-128`），`applyDone`（`ui/public/app.js:235-258`）无视 `source` 直接置 `status:"done"`；随后返工轮的审批卡因 `operable = isPending && isRunning` 为 false 而不渲染按钮（`app.js:687-691`），`pending.respond` 永不被调用，loop 永远 await | 源码链完整；R1 将补脚本化回归复现 | 运行不可恢复地卡死，用户无任何操作入口 | 段终止与 run 终止在事件层显式区分；只有 run 级终止才收敛 UI 状态与过期审批 |
| **V-02** | **审批决策不进事件流**。决策只写在浏览器内存（`app.js:433`），服务端 `run.events` 无记录 | 浏览器实测：两次实际**已允许并执行成功**的审批（日志含 `tool_result: 已写入 42 行`），刷新后审批卡与"审批记录"均显示"已过期" | 违反 v1 报告 §6 对只读审计记录的要求；多标签页/多机器看到互相矛盾的状态 | 决策与过期均由服务端事件驱动，任意客户端重放后得到同一份审计记录（动作/对象/决策/主体/时间） |
| **V-03** | **审批卡跨轮串卡**。`markApprovalResolved` 按 `toolUseId` 全量匹配；返工轮复用同一 `toolUseId` | 源码；实测返工运行出现两张完全相同、无法区分轮次的审批卡 | 一次点击改写历史审批记录，审计失真 | 审批以「请求序号」为唯一键，同 id 跨轮互不影响 |
| **V-04** | **`stopReason` 六值被压成两值**。`src/types.ts` 定义 `completed / max_tokens / max_turns / budget_exhausted / refusal / error`，`app.js:247` 只判 `error` | 源码 | `max_turns` / `budget_exhausted` / `refusal` / `max_tokens` 全部显示为绿色"已完成"。按项目结论，`max_turns` 与 `error` 恰是 verifier 救不了的两类——界面反而告诉用户一切正常 | 六值分档呈现 + 人话解释 + 可执行补救提示；对齐 CLI（`src/cli.ts:573`） |
| **V-05** | **SSE 断线即误判过期且不重连**。`index.html:289-301` 的 error 处理主动 `es.close()`（杀掉浏览器原生自动重连）并把所有 pending 审批标为 expired | 源码 | 一次网络抖动就让活着的审批卡消失，run 挂起且无应答入口 | 断线只提示不改状态；带 `Last-Event-ID` 自动续传；重放幂等 |

## 3. 设计主线（本轮的组织原则，非装饰）

**主线一 · 四决定因素**：A1 命题指出模型能力固定时 agent 表现的差异全部落在
Loop / Tools / Context / Verification 四处。CLI 是时间序的，Web 控制台不应只是"带标签的 CLI"——
首屏呈现这四个面的状态，日志是它们的下钻内容。

**主线二 · 认知诚实**：界面先说清自己知道什么、不知道什么、哪些只是意见、哪些已不可挽回。
四条可执行直译：

1. `✔ 已核实` / `⋯ 无法核实` / `◈ 主观意见` **同级同权重**排布，后两者不做成脚注。
2. `⚠ 通过（有备注）` 独立成态，不被 passed 的绿色吞掉。
3. **不可逆**（compaction 置换的 `tool_result` 原文永不可恢复）有独立视觉语域，与普通警告可区分。
4. **数字必须带口径**：墙钟 vs 步和、`executionUsage` vs `main.usage`、当前轮 vs 全 run 累计。

## 4. 验收标准

P0 项不得以"后续优化"名义延期。

| 编号 | 验收条件 | 验证方式 |
|---|---|---|
| **AC2-01** | 返工轮的审批可正常应答，运行能收尾；段终止不再被误当作 run 终止 | 脚本化模型跑 `main → verifier(fail) → rework(需审批)`，服务端契约测试 + 浏览器实测 |
| **AC2-02** | 审批审计记录在**刷新后**仍完整正确（动作/对象/决策/主体/时间），任意客户端重放结果一致 | 契约测试 + 浏览器刷新实测 |
| **AC2-03** | 同一 `toolUseId` 跨返工轮产生的审批互不串卡 | reducer 测试 + 契约测试 |
| **AC2-04** | 六种 `stopReason` 分档呈现且带补救提示；`max_turns` / `error` 明确告知"核查救不了这一类" | 六值全覆盖 reducer 测试 + 视觉走查 |
| **AC2-05** | SSE 断线自动重连、不误判过期；重放幂等（同批事件重放两次状态深相等） | 幂等性测试 + `Last-Event-ID` 契约测试 |
| **AC2-06** | `AGENT_PACK` 指定的包，其核查白名单/指令/rubric 与护栏在 Web 上真实生效；`/api/harness` 输出与 `npm run cli` 的包打印逐字段一致；`AGENT_VERIFY_RUBRIC` 能产出非空 advisory | 契约测试 + 真实模型端到端一次 |
| **AC2-07** | 界面上每个数字都有口径标注；返工运行的成本用 `executionUsage` 而非末轮 usage | 契约测试 + 视觉走查 |
| **AC2-08** | 逐轮裁决实时可见；返工序列 F→F 与 F→P 可辨 | 契约测试 + 视觉走查 |
| **AC2-09** | 上下文水位按**最近一轮输入**计算（非累计）；token 三分与缓存命中可见；compaction 标注不可逆 | 派生模型测试 + 视觉走查 |
| **AC2-10** | 直播中焦点连续停留 30 秒不失焦；拒绝理由输入不被清空；日志滚动位置不跳 | 浏览器实测 + jsdom 细粒度更新测试 |
| **AC2-11** | 1000 条事件回放单帧渲染 < 16ms 且只触发一次渲染 | 性能测试（spy 计数） |
| **AC2-12** | 日志按段分组、来源与轮次可辨、`↺` 返工分界在位；工具结果显示名字而非 ID；耗时人类可读且执行/等待分列 | 视觉走查 + 派生模型测试 |
| **AC2-13** | 首屏无需下钻即可读出四个决定因素的状态；两个"第一眼"场景（正在跑的 run／已完成且核查未通过的历史 run）逐条满足 | 首屏检查 + 可用性走查 |
| **AC2-14** | 双主题（浅色默认 + 暗色）下正文对比度 ≥ 4.5:1、大字号/非文本组件/焦点 ≥ 3:1；两主题令牌名集合相等；主题定义块外裸十六进制色值 = 0 | WCAG 实算门禁（`describe.each` 双主题） |
| **AC2-15** | 四视口（390×844 / 768×1024 / 1280×720 / 1440×900）× 双主题无页面级水平滚动；200% 缩放可用 | 响应式回归（**全矩阵，不得只跑 1280**——字号上抬是 R-02 最可能的回退点） |
| **AC2-16** | axe-core 六画面 violations = 0，浅色与暗色主题均通过 | 常驻门禁 |
| **AC2-17** | `npm run ui` 可启动，默认绑 `127.0.0.1` | 手工验证 |
| **AC2-18** | **v1.0 全部条目未回退**：R-01~R-08、P2 令牌统一、AC-01~AC-10 逐条复验 | 逐条复验 + 现有测试全绿 |

## 5. 本轮明确不做

写在这里是为了避免被误判为回退：

并行编排 `runPlanned` / DAG / 甘特视图（数据契约已预留：SSE `source` 放开为字符串）·
中止运行 · 追加指令 · 日志搜索与导出 · v1 报告 §10 提到的"产物/变更 diff"面板（缺 diff 数据源）·
memory 工具在 Web 上的接入 · run 持久化（重启仍丢）· 监控基线（运营项）。
