# 案例 #2：并行编排首次真活——src/ 模块参考文档（2026-08-04）

v1.1 合并回 main 后的第一个 `--plan --parallel` 真实交付。任务一句话：为仓库生成
`docs/reference/` 模块参考（三份分组文档 + 索引，签名必须与源码逐一一致）。

## 配置（研究结论直接落地）

- `AGENT_PLAN_PROTOCOL=structured`：fan-out 形状任务用结构化拆分协议——
  拆分决策由宿主规则输出，不掷硬币（freeform 实测 ~50/50 摇摆）
- `--plan --parallel=3`：DAG 调度，并行度 3（收益曲线背书的 cap）
- 执行模型 deepseek-v4-pro（文档准确性优先）；MCP 禁用（不碰硬件工具面）

## 结果

计划形状 `s1[] s2[] s3[] join[s1,s2,s3]`（结构化协议一次到位，零摇摆）；
4/4 子任务执行并核查通过。

| 子任务 | 产物 | 耗时 |
|---|---|---|
| s1 | core.md（6 模块，366 行） | 179.1s |
| s2 | orchestration.md（5 模块，464 行） | 212.8s |
| s3 | tools-periphery.md（10 模块，457 行） | 464.2s |
| join | README.md 索引 | 47.8s |

**子任务阶段墙钟 512.0s vs 串行合计 903.9s——并行净省 391.9s（−43%）**；
关键路径再次精确成立：512.0 = s3(464.2) + join(47.8)。全程（含 planner）545.7s。

## 过程亮点

1. **verifier 独立复核动真格**：s3 verifier 重读全部 10 个源文件逐一比对签名，
   顺带确认执行者自述的 4 项修复"全部实际落地"；其 bash 取证尝试（grep -c/file）
   被只读约束正确拦截后改用 read_file 完成——防线与韧性同时在场。
2. **join 收口纪律生效**：索引 agent 自检表明确声明"未读取任何 src/ 源文件，
   内容完全源自三份分文档"——结构化协议把收口句写进 join 任务书的设计起效。
3. 三个写集不相交的分片并发写文档、三个 verifier 并发连读源码，零冲突零审批事故。

## 结论

调度器在真实交付上复现了 eval 数据：墙钟贴关键路径、并行省时不省 token、
协议消除拆分摇摆。并行编排从研究线毕业进入生产可用。
