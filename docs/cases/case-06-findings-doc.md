## 三个核查行为观察(本案研究载荷)

1. **结构化部分裁决替代了核查饥饿**:join 的 verifier 无白名单跑不了 wc/git,
   但没有重演案例 #4 的 fail-closed 空转——它能判的判、不能判的逐条列出移交
   人工(AC3 八条数字/AC1 行数/AC5 git 状态),passed=true 带明细保留意见。
   差异变量就是任务书那句"判不动就自陈判法"——**一句纪律改变了不可核验时的
   行为模式**(杠杆定律:歧义点上一句话就够,这次的歧义点是"查不了时怎么办")。
2. **passed 带 ⚠ 的价值第二次实证**:s3 verifier 放行的同时点名"7/10→10/10
   归属错了报告"——该缺陷在 join 阶段被修正,没流进终稿。裁决 summary 浮出
   机制(c1a7144)上线当天即两次立功。
3. **裁决端字面纪律反向验主**:s1 verifier 抓到任务书自身笔误("5 个子主题"
   实列 4 个),按字面枚举裁决并注明分歧——verdict-side rule-precedence 的
   约束对象包括委托方自己。

## rubric-verifier 设计种子(从本案提取)

- 裁决形态从布尔升级为**三值明细**:可判项(证据+判定)/不可判项(移交清单)/
  主观项(自陈判法+置信度)——本案 verifier 在一句纪律的提示下自发逼近了这个
  形态,说明机制化成本不高。
- 主观项不触发自动返工,进入宿主决策面(summary 浮出机制已就位)。
- "用参考物代替文字规则"(案例 #5 的 demo 范本经验)可能是 rubric 的领域内
  近似解;通用解仍开放。

提炼类任务在三角编排下可交付且并行收益依旧(44%);主观验收的缺口真实存在,
但其形态不是"verifier 乱判",而是"缺一个让它诚实降级的协议"——rubric-verifier
的第一块拼图已经有了。
