## 三、S1/S2 里定下的六条

1. **备份不能留在工作区**;冻结清单必须穷举(哪些文件"一个字不许改")。
2. **"可布线的摆位"≠"合法的摆位"**:摆位阶段就要跑 DRC(courtyard/丝印压焊盘)。
3. **执行者不能结构性编辑 8000 行文件**——三发同形失败。宿主用 pcbnew API 从网表重建永远干净:
   `examples/case11_build_devboard.py` 是那条管线的范本。→ backlog:kicad 包的结构化编辑工具。
4. **栅格要与器件节距对齐**:0.1 栅永远差 0.05 踩不进 LQFP 0.5mm 引脚巷道,0.125 才行(kit `GRID`)。
5. **GND 缝合的顺序**:信号先走、GND 最后缝;逃逸沿焊盘长轴向体外;缝合 via 与信号 via 的孔距 0.9。
6. **SWIG 毒化**:`board.Remove()` 之后同进程再算几何会读到坏对象 → 拆/算/落板**分进程**
   (kit 里 `route_repair`(纯计算 → actions.json)与 `apply_actions`(落板)分开,`move_parts` 分 rip/move 两步)。

## 四、开发板 PCB:自动布线要守规矩,靠约束 + 审计 + 混合返工

委托方问:"如果自动布线会不会不符合我们之前成熟工程的规则?"——回答落成了方法。

### 4.1 判据先写(量产校准)

在跑任何布线器之前,先剖析委托方量产仓库两块 KiCad 原生 L151 板(WR350 / AT_v0.74),
把"成熟工程的规则"量化成 7 条体检(`audit_routing.py`,阈值不许为结论好看而改):

| # | 判据 | 来源 |
|---|---|---|
| 1 | B.Cu 走线总长 ≤ F.Cu 的 40% | WR350 底层走线只有顶层的 1/6——**底层是参考面** |
| 2 | 最长 B.Cu 单段 ≤15mm | 底层只做短逃逸 |
| 3 | via ≤80 且 ≤0.35/段 | 两板 via 经济性 |
| 4 | 晶振盒内两层无他网 | 惯例 |
| 5 | GND 底池轮廓数=1(孤岛 0) | WR350 单一轮廓 |
| 6 | 线宽 ≥0.25 | 我们比量产 0.15–0.2 保守 |
| 7 | via 0.6/0.3 | 手焊调试板口径(量产主流 0.5/0.3) |

顺带三个对既有纪律的诚实修订:**曼哈顿是执行者脚手架不是行业惯例**(量产 45° 占 35–49%);
布线前先铺底层 GND 池;去耦 3mm 是目标不是死线(量产 6mm 也在跑)。

### 4.2 freerouting headless(2.3.0)踩过的坑

- JRE 21 起不来(class 69)→ JRE 25 便携装;
- 同目录同名 `.rules` 会弹"导入已存规则?"确认框阻塞 headless(委托方截图报警,选"是"无害,根因是挪走那个文件);
- `-is/-us` 六组扫掠**结果完全相同**——它们只动优化阶段;
- 想给层代价:DSN 里注入 `autoroute_settings` → headless 下 0 网可布,弃;
- neckdown 会把线缩到 0.2 → `freerouting.json` 里 `automatic_neckdown:false`;fanout 也关。
- 让它守规矩的手段只有三样:**约束**(GND 池导出成 plane、规则区导出成 wire_keepout、网类)+ **事后审计** + **混合返工**。

### 4.3 混合返工循环(DRC 驱动)

freerouting 出的 84/84 全通版有 12 条底层长跑道切池、孤岛一片。返工不是重跑布线器,而是:
`rip_runs`(拆切池长跑道)→ `rework_loop.ps1`:拆冲突 → 逐轮清悬空 → DRC 未连接对 → `restore.json`
→ `route_repair`(0.125 栅两层 A*,F 优先,B 代价 ×4,GND 端点 DIVE 下潜入主池打针)→ `apply_actions` → `mitre` → DRC。
两条硬教训:嵌套扇出**由内向外**恢复(PB14→PB13→PB12,外圈先占道内圈无路);
`rip-box` 一次把 24 个 GND 缝合 via 当"孤 via"删光——回滚快照,`rip_runs` 从此 GND 强制保留。

### 4.4 委托方三次红框(每条都成了纪律)

1. "C8 意义不明的布线 / Y2 和单片机旁边用了 90° 走线 / 锐角 45° 走线" → `mitre.py` 全板拐角整形
   (度数 2 拐点 → 八向 L 形或 45° 斜角,逐遍收敛),v6 拐角统计 45°×417 / 90°×2 / 41°×1——
   残留三处都是焊盘入口 <0.4mm 的微折(`mitre --dry` 如实列出,视觉不可见,未再动);
   包纪律 4c"拐角只允许 45° 倍数,不出现看不出理由的绕行"。
2. "没有 GPIO 排针的对应引脚丝印,调试排针、boot 排针同样如此" → `silk_labels.py`(蓝药丸式逐引脚标注)+
   `place_silk.py`(位号安置把板级文本当障碍——否则位号压标注);SW1/C7/D1/R1 为标注让道挪位;
   包纪律 4d"排针逐引脚丝印,一个不落"。
3. "过孔 0.3 内径 0.5 外径 0.152 线间距再看看对不对 / 嘉立创能加工就行,按嘉立创标准来" →
   查嘉立创能力表(线宽/距 ≥0.10、0.3 孔+≥0.45 外径标准价、丝印线 ≥0.15 字高 ≥1.0、阻焊桥 0.10)
   写进板级最小约束(`jlc_rules.py`);实物保持 0.25/0.20/0.6-0.3(更保守);`fab_check.py` 对照打印。
   顺带发现:**板级规则活在 `.kicad_pro` 里**,只拷 `.kicad_pcb` 的快照读回默认值。

### 4.5 结果

v6(`v6-DEVBOARD-JLC-drc0`):DRC 0(嘉立创口径 + parity)、ERC 0、审计 5/7
(via 81 vs 80;孤岛主池 + 12.7mm² 口袋 + 1.0mm² 碎片,均已桥接)、417 个 45° 角、
48 条排针/板名丝印、`L151-DEV-v1-JLC-gerber.zip`。3D 双面渲染与原理图 PDF 在 `preview/`。
两项审计不满分**如实记录**而非改阈值——委托方可决定是否继续压 via/孤岛。

## 五、定论

1. **能力缺口的形状不变,答案升级了。** 案例 #9 说"文本模型看不见画布 → 从问题里删几何";
   本案例再进一步:文本模型也**不能结构性编辑大文件**——三发同形失败之后,
   任务书写得再严也没用,答案是给它**结构化工具**(rip/restore/mitre/audit),
   宿主工具箱就是那些工具的原型。杠杆定律第三次证成:修环境,不是提示词,不是更大的模型。
2. **自动化要守规矩 = 约束 + 审计 + 返工,不是调布线器旋钮。** 判据先于结果、来自量产板而非直觉;
   审计不过回到拆/返工,阈值不动。
3. **委托方的肉眼是最贵的判官,要把它的每一次开火固化。** 三次红框 → 三条纪律 + 四个工具;
   下次不该再靠人眼抓 90° 折角和缺失的排针丝印——`mitre --dry` 与丝印核对已进 verifier 体检单(包 #8)。
4. **观测装置再一次差点冒充被测对象**:`.rules` 弹窗、`.kicad_pro` 缺席读回默认值、SWIG 毒化——
   三条都是装置性质,先分清再下结论(发现 49 家族)。
5. **工具必须活在仓库里。** 会话临时目录被清空过一次,重写了两小时;这次全部脚本参数化入仓
   并在 v6 副本上冒烟(README 有记录),下一案例从 `eval/kicad-host-kit` 起步。
