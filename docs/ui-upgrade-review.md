# Agent Harness 桌面级 UI 升级评审报告

> 评审日期：2026-09-05
> 评审对象：agent-harness v1.3.0 Web 控制台（`ui/`）+ `cross-app/` 桌面外壳
> 方法：架构静态分析 + `.codex/` 真实截图目检 + 市面成熟 agent 产品对标调研
> 前置输入：[ui-current-state-report](ui-current-state-report.md)（UI 现状逐文件分析）

---

## 一、项目架构速览（升级的技术前提）

| 层 | 事实 | 对 UI 升级的含义 |
|---|---|---|
| 核心契约 | `TurnEvent` 异步事件流 + 约 20 个 REST 端点 + SSE 推送 | **新 UI 只需消费同一契约，核心引擎不用动** |
| 宿主 | CLI（`src/cli.ts`）与 Web（`ui/server.ts`）平级，复用同一核心 | UI 是"宿主"而非"附属"，升级空间不受引擎限制 |
| 持久化 | `.agent-run-history/<runId>/` 四文件归档，界面状态全部由事件重放长出（V-05 幂等） | 任何新视图（看板、时间线、统计）都可从事件流派生，无需改数据层 |
| 前端 | 零构建原生 ES 模块；`app.js` 7 795 行 + `index.html` 内联 1 750 行控制器 | **最大的技术债集中点** |
| 后端 | `ui/server.ts` 6 996 行单文件，路由/审批/预算/恢复/持久化全塞里面 | 加新端点（通知、调度、设置）前先拆路由层 |
| 桌面化 | `cross-app/` 已有 Electron + Capacitor 外壳，内含 8 月 13 日的**已漂移静态副本** | 升级必须先解决双副本同步问题，否则桌面端永远是旧 UI |

## 二、现有 UI 的强项（必须保留的资产）

这些是这个 UI 相对于市面产品的**差异化优势**，升级时不能丢：

1. **监督式 agent 交互完整**：工具审批（含拒绝理由）、计划确认门、ask_user 一屏 1~4 题、预算当场追加——这套"人在回路"设计比 Claude Desktop 的审批粒度更细。
2. **透明度业界领先**：思考过程、工具调用耗时、缓存命中率、token 成本逐段织进时间流；四决定因素仪表盘（Loop/Context/Tools/Verification）是研究型产品独有的。
3. **可中断、可续跑、可 fork**：停止语义诚实（"已完成的写入不会回滚"），崩溃后从检查点续跑——多数消费级产品（ChatGPT/Manus）做不到同 runId 恢复。
4. **设计系统已成型**：三层令牌 + 4 主题 + WCAG 对比度实算 + 无障碍闸门测试（axe-core），底子比很多创业公司产品扎实。
5. **零依赖安全纪律**：markdown 先转义再变换、链接协议白名单、手写高亮——供应链风险几乎为零。

## 三、不足点（按严重度排序）

### 3.1 工程结构问题（阻塞一切升级）

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| E1 | **巨型单文件**：`app.js` 336 KB / `server.ts` 311 KB / `index.html` 内联控制器 1 750 行 | ui-current-state-report §8.1 | 任何新功能都要在巨型文件里动刀，冲突率与回归风险随规模指数增长 |
| E2 | **`cross-app/` 静态副本已漂移** | markdown.js 在 cross-app 是 9 月 5 日、app.js 是 8 月 13 日 | 桌面端（Electron）跑的是旧 UI，升级后两端必然不一致 |
| E3 | **零构建约束未定生死**：当前无法引入组件框架 | report §8.2 | 不解决这个决策，"全面升级"无从谈起 |
| E4 | 遗留文件：`ui/history-backup.ts` 疑似死代码、Layer 3 兼容别名约 237 处 | report §8.4 | 认知负担，新人读代码要先分辨哪层是真的 |

### 3.2 交互能力缺口（对标后确认的真实缺失）

| # | 缺失 | 谁有 | 用户痛点 |
|---|---|---|---|
| F1 | **无命令面板（Cmd+K）** | Claude Desktop、Cursor、Linear、几乎所有 2025 年后产品 | 功能藏在 composer 旋钮和折叠面板里，发现性差 |
| F2 | **快捷键只有 2 个**（Ctrl+Enter / Esc） | Cursor、Claude Code 桌面端 | 重度用户（跑 agent 的人群画像）离不开键盘流 |
| F3 | **无独立设置页**：设置 = composer 折叠旋钮 | 所有成熟产品 | 主题、模型、审批策略、工作目录、记忆、快捷键——没有统一入口 |
| F4 | **无文件工作区视图**：只有产物卡列表 | Claude Cowork、Devin、Cursor 的文件树 + diff 审查 | agent 改了什么文件、改了哪几行，无法集中审查——**这是监督式产品的致命短板** |
| F5 | **无全局搜索**：只能搜对话标题 | ChatGPT、Claude 均可搜对话正文 | 几十次运行后找不回"那次跑 ad7793 的结论" |
| F6 | **无系统通知**：agent 跑完/需要审批时用户不知道 | Claude Cowork 手机推送、OpenClaw、Nimbalyst | 长任务要盯着屏幕等，违背"委托式"产品逻辑 |
| F7 | **无定时任务/后台任务管理** | ChatGPT Scheduled Tasks、Claude Cowork cron、Kimi Work | 有 `.agent-runs.jsonl` 台账却没有"明早 6 点自动跑"的入口 |
| F8 | **无并行会话管理视图**：侧栏只是线性列表 | Devin Desktop Agent Command Center、Nimbalyst kanban、Conductor | 后端支持 DAG 并行编排，前端却看不到"多个任务同时在跑"的全局态 |
| F9 | **无记忆可视化**：`.agent-memory/*.md` 无界面入口 | Claude Project memory、ChatGPT Memory 设置 | L5 记忆是项目特色，用户却不知道 agent 记住了什么、无法纠正错误记忆 |
| F10 | **无语音输入** | ChatGPT 全平台 | 桌面产品的标配输入方式（可选优先级） |

### 3.3 信息架构与视觉问题

1. **对话流信息密度过载**：从截图看，长任务的时间流被"思考过程 803 字 / 2206 字 / 1174 字…"大量同质卡片刷屏，真正的结论（施敢当的总结）被淹没。需要一个"过程/结论"的阅读模式切换或自动摘要折叠。现状虽有"过程/对话两种读法切换"，但默认视图仍以过程为主。
2. **侧栏浪费纵向空间**：每个对话卡片占 4 行（状态+标题+时间），一屏只能放 6~7 个会话；无置顶、无星标、无归档分组。
3. **右栏 rail 与仪表盘抽屉职能重叠**：Progress/产物/计划看板在右栏，Loop/Context/Tools/Verification 在底部抽屉——两类"监控信息"分属两处，用户要养成两套心智模型。
4. **产物呈现降级为"文件列表"**：agent 产出的 HTML 站点、表格、图片只能"下载/在文件夹中显示"，没有内联预览画布（对比 Claude Artifacts / ChatGPT Canvas 的双栏画布形态）。预览端点已有（`/artifact?path=`），但呈现是链接而不是工作区。
5. **空态引导单薄**：欢迎页只有示例任务，没有"这个工具能做什么"的结构化导览（对比成熟产品的 onboarding 流程）。
6. **品牌感弱**：工具型控制台审美（深棕黑+陶土橙）本身成立，但缺少品牌识别元素（图标、logo、动效签名），衬线大标题是唯一的"编辑感"，在深色主题下辨识度不足。

### 3.4 桌面化的功能缺口（cross-app 现状）

- Electron 壳只是"包了一层窗口"，**没有用到任何桌面原生能力**：无托盘、无全局快捷键唤起、无系统通知、无开机自启、无离线任务队列。
- 对比 Claude Cowork"合上电脑任务照跑、手机看进度"，本项目宿主重启后运行即归档不可续跑（截图 composer 下方已有诚实提示，但产品层面没有解决"后台执行"这个委托式 agent 的核心承诺）。

## 四、市面成熟 agent 产品形态对标

调研截至 2026-09，主要产品形态：

| 产品 | 界面形态 | 对本项目的启示 |
|---|---|---|
| **ChatGPT 桌面端**（Chat/Work/Codex 三 Tab） | 一个 app 收三种模式；Work 模式交付文档/表格/PPT/Sites；Scheduled Tasks；自动 Memory + Projects | 模式化导航（Tab）比"一个对话干所有事"清晰；定时任务是标配 [中关村在线](https://news.zol.com.cn/1223/12238718.html "citation") |
| **Claude Desktop / Cowork** | Chat/Code/Cowork 三模式；Artifacts 画布；定时任务；VM 沙箱；桌面+网页+手机跨端续跑；任务需审批时推送手机 | Artifacts 双栏画布是"产物一等公民"的标杆；跨端续跑定义了委托式体验 [网易](https://www.163.com/dy/article/L1KMEKMH0511D3QS.html "citation") |
| **Kimi Work** | 独立桌面 agent；专业 Skills（金融/法律/科研）；子 agent 集群；看板（Dashboard/Widget）组织持久产物 | 垂直领域包 + 持久可视化看板，与本项目的 DomainPack 思路同源 [掘金/sgknight](https://www.sgknight.cn/2026/06/24/2026/06/kimi-work-vs-cowork/ "citation") |
| **Devin Desktop**（原 Windsurf） | Agent Command Center：本地+云端多 agent 统一监管；PR 审查；实时预览 | **多会话指挥中心**是"跑多个任务"人群的核心界面 [Braintrust](https://www.braintrust.dev/articles/best-ai-coding-tools-2026 "citation") |
| **Nimbalyst / Conductor** | 并行会话看板（kanban）+ git worktree 隔离 + 内联红绿 diff 审查 + 完成推送通知 | 小团队验证过的形态：看板 + diff 审查 + 通知三件套 [Nimbalyst](https://nimbalyst.com/blog/best-ai-coding-agents-2026/ "citation") |
| **OpenClaw** | 把聊天 app 变成 agent 控制台；后台任务结果推回聊天；菜单栏伴侣 | "通知优先"：agent 是异步同事，界面是收件箱 [artificialanalysis](https://artificialanalysis.ai/zh/agents "citation") |

**收敛出的行业共识（2026 年桌面 agent 产品的及格线）：**

1. **委托式闭环**：派发任务 → 后台执行 → 完成/需决策时通知 → 任意设备查看结果
2. **产物一等公民**：文档/表格/网站不是聊天记录里的附件，而是可编辑、可预览、可迭代的画布
3. **并行会话监管**：同时跑 N 个任务，有一个全局视图（看板/指挥中心）看状态和干预
4. **定时任务**：cron/定时器入口，任务不依赖人在场
5. **审批的人因设计**：需要人决策时主动找到人（通知），而不是等人回到屏幕前
6. **记忆可审查**：agent 记住了什么，用户能看、能改、能删

**本项目 vs 及格线：第 5 点前半（审批设计）领先，其余全部缺失。**

## 五、升级建议（分三个梯队）

### P0 —— 不修则升级白做（工程基础）

1. **决策零构建约束的去留**：建议保留"服务端零依赖"，前端引入轻量构建（esbuild 单文件打包即可，不必上 Vite 全家桶），把 `app.js`/`index.html` 内联控制器拆成按面板的模块。
2. **消灭双副本**：`cross-app/` 改为构建期从 `ui/public` 生成，删掉手工拷贝的静态副本；顺手清理 `history-backup.ts` 与 Layer 3 别名。
3. **拆 `ui/server.ts` 路由层**：按域拆（runs/approvals/artifacts/settings/history），为新端点腾位置。

### P1 —— 补到行业及格线（功能）

4. **命令面板（Cmd+K）**：新建对话/切换会话/切主题/切工作目录/跳设置——键盘流入口，半天原型可见效。
5. **设置中心页**：主题、模型与角色、审批策略、工作目录白名单、记忆管理、快捷键一览。把 composer 旋钮里的高级项迁过去，composer 只留高频。
6. **变更审查视图（diff workspace）**：以运行/会话为单位聚合"agent 动了哪些文件、每处 diff"，支持内联预览——监督式产品最该有而没有的东西。
7. **系统通知 + 任务中心**：运行完成、审批待决、预算耗尽三类事件发桌面通知（Electron 原生 `Notification`）；侧栏加"待你处理"聚合入口（现在审批卡只出现在打开的那个会话里）。
8. **定时任务入口**：`schedule` 触发器 + 任务列表页，复用现有 run 历史体系。
9. **全局搜索**：搜索对话正文与产物文件名（transcript.jsonl 已在盘上，索引成本可控）。
10. **记忆面板**：`.agent-memory/*.md` 的只读列表 + 编辑入口，让 L5 记忆从黑盒变成可审查资产。

### P2 —— 做出差异化（形态）

11. **产物画布（Artifact Canvas）**：右栏升级为双栏工作台——HTML 站点内嵌 iframe 预览、表格/图片原生渲染、多版本切换；预览端点已有，差的是呈现层。
12. **并行会话看板**：侧栏之上加一个"运行中"指挥中心视图，卡片显示各 run 的进度/预算/待审批数，点击直达干预点。
13. **过程/结论双模式阅读**：默认视图收敛为"结论 + 关键步骤摘要"，过程时间流一键展开——解决思考卡片刷屏问题。
14. **桌面原生能力**：托盘驻留、全局唤起快捷键、开机自启、离线时任务排队。
15. **语音输入**（可选）：浏览器的 Web Speech API 即可起步。

### 明确不建议做的

- ❌ 推倒设计系统重做视觉风格——三层令牌 + 4 主题是稀缺资产，问题在布局密度不在配色
- ❌ 上 React/Vue 全家桶重写——投入产出比低，且丢掉零依赖安全纪律；模块拆分 + 轻量构建已足够
- ❌ 做多用户/账号体系——本地工具定位清晰，不要为了"像 SaaS"而做
