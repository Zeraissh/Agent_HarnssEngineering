# 12 · 共享宿主真机评测纪律

操作纪律，不进产品逻辑。本文件把仓库已经付过学费的结论收成「多人设、一台真实 Web 宿主」清单。
编号与 [`docs/12-enterprise-review-checklist.md`](12-enterprise-review-checklist.md) 并存：那份是企业评审勾选清单，本文件是评测怎么跑、怎么判。

成熟度台账仍是 [`docs/08-maturity-optimization-checklist.md`](08-maturity-optimization-checklist.md)。本层补的是 **BASE-04 的软件切片**（真实模型 + 真浏览器 + 共享宿主并发），不是再写一套 vitest，也不替代 BASE-04 里尚未同时验收的 Electron / Android / 容器 canary / STM32 HIL。

---

## 这层在既有仪器里的位置

四层已经在仓里。本层打的是它们之间的缝：CLI 产物对、单浏览器 mock 绿，不等于多人共用一台宿主时对话还能用。

| 层 | 仪器 | 锁什么 | 本层不重复的理由 |
|---|---|---|---|
| L0 | `npm test` + `FakeModelClient` | 纯函数、reducer 投影、契约 | 零真实 token、无浏览器运行时 |
| L1 | `npm run eval:deterministic`（`dist` + mock） | 进程边界、退出码、圈禁、编排失败恢复 | 不经 Web、不经真实模型 |
| L2 | held-out CLI（`AB_SUITE=heldout`） | flash 档 CLI 产物 | 不是 Web 对话，无侧栏/SSE/多 run |
| L3 | [`eval/e2e-web.ts`](../eval/e2e-web.ts)（Playwright + mock） | 审批点按、SSE 续传、崩溃/热恢复 | **零真实 token、单浏览器、无多对话争用** |
| L4 | 本层：共享宿主 + 真人设 + 真实模型 | 并发下 UI/逻辑会不会挡别人正常使用 | 见下 |

L0 绿 ≠ 真机对。隐藏标签页的 `requestAnimationFrame`、`[hidden]` 被作者 `display` 压过、Windows 路径、`workdir` 未 `resolve`、纯函数与控制器的缝（段终止被当成 run 终止），单测按设计覆不住。

## 拓扑与波次

- **一台宿主**。默认 `http://127.0.0.1:4173`（`ui/serve.ts`）。各人设独立 scratch 工作目录，共侧栏、共 SSE、共日预算、共 `maxActiveRuns`。
- **准入上限**。真实宿主缺省 `maxActiveRuns = 4`（[`ui/server.ts`](../ui/server.ts)：`options.maxActiveRuns` > `AGENT_UI_MAX_ACTIVE_RUNS` > 4）。第 5 个在飞 run 走 429，正文含 `Active run limit reached` 与 `activeRuns`。注入测试宿主不走这条缺省（`Number.MAX_SAFE_INTEGER`），勿拿测试宿主的「能开很多」当生产行为。
- **波次，不要蛮力并行。** 模型槽 ≤ 3。第 4 个在飞槽留给观察员必要时的 API 探针，或留给第二波（计划/战役）等空槽再提交。6 个人设里同时烧模型的不得超过 3，避免第 5 个 run 的 429 被误判成「产品坏了」。
- **上限怎么测。** 用 API 单发探针打第 5 个准入，不要再开一个人设去挤掉别人的槽。在飞的 4 个必须不受影响。
- **目录隔离。** `AGENT_UI_EXCLUSIVE_WORKDIR` 保持缺省（只告警不拒）。本层靠 scratch 分目录防互踩；同目录双开若仍互踩，才是路径归一化缺陷。
- **产品仓只读。** 禁止把本仓库（或任何正在被评测的源码树）选作任务 `workdir`。编码人设用独立 scratch 小项目。

### 开工（协调者，先于任何人设）

1. `npm run doctor`。确认本轮约定的模型名（若压弱：执行者 / 核查者 / planner 同档）。进程环境若残留 `ANTHROPIC_BASE_URL` 压过 `.env`，先清（README 已知坑）。
2. 查宿主端口：只认 `Listen` 且 `OwningProcess > 4`。TimeWait 不是占用。没有再拉起；已有则 **attach，不重启**。
3. 快照 `GET /api/harness`、`GET /health`、`GET /ready`：模型名、日预算剩余、`maxActiveRuns`、MCP、识图/生图等是否在场。缺的能力记「干净缺席」，人设降级，不编造。
4. 每人设一个 scratch 目录，经 UI「添加目录」或 `AGENT_UI_WORKDIRS` 进白名单。证据根另建，每人设子目录：时间线、截图、`runId`、关键 API JSON。
5. 协调者只放行波次与收证据，不与子代理抢同一浏览器锁。

### 人设与槽位（可复用的默认切法）

同时烧模型的人设 ≤ 3。壳层与观察不占模型槽。计划/战役等宽任务放第二波。

| 角色 | 吃模型槽 | 工作目录 | 备注 |
|---|---|---|---|
| 对话用户 | 1 | 独立 scratch | 主路径：空态、同 run 追问、队列、引用、停止、`ask_user`、勾一次核查 |
| 设计/办公 | 1 | 独立 scratch | 设计模式入口 + 短模板；追问改一处；扫产物/预览 |
| 编码 | 1 | 独立小项目 | 开核查。**禁止**对本仓库开编码包 |
| 计划/战役 | 等空槽 | 独立 scratch | 可拆任务；先看计划确认门再批准；战役若可见只开 1 个子对话 |
| 操作员 | 基本不占 | 只点白名单 | 壳层走一遍：搜索/设置只读/项目/记忆/定时草稿/命令面板 |
| 争用观察 | 不提交长任务 | — | 切换别人的 run、藏后台再回来、对照重放事件 |

覆盖记「打得开 / 有内容 / 挡住主路径」，未测必须写原因（能力干净缺席、无空槽、人设降级）。

## 十一条原则

原则全部来自本仓库已有结论，只是收成清单。执行时按编号引用，不要现场发明第十二条。

1. **先排除仪器，再谈产品。** 开工快照 `/api/harness`。模型名不是本轮约定、MCP 该缺却在、日预算已封盘（`AGENT_UI_DAILY_TOKEN_BUDGET=0` 或账本触顶）——先停。环境噪声写成缺陷，后面每条都脏。A/B 研究三次推翻都先撞到仪器，再谈策略。

2. **被测对象 ≠ 观测装置。** 子代理用浏览器当用户。对错看 DOM、HTTP、落盘 `.agent-run-history/<runId>/events.jsonl`（以及 `GET /api/runs/:id/events`），不看代理自己的转述。协调者不当第五个操作员去点同一套控件，也不与子代理抢同一浏览器锁。真机结论先问：这是被测对象的性质，还是观测装置的性质。

3. **能行为验证就别用字符串。** 「追问成功」= 同一 `runId` 的 `POST /api/runs/:id/messages` 返回 200，且时间线出现新的 user 回合。「计划没掐死」= planner 自己的 `done` 之后，事件流仍能收到 `plan_result` / 子任务事件（历史真缺陷：`mode=plan` 且未勾核查时，客户端把段终止当成 run 终止并 `es.close()`）。禁止「感觉还行」。

4. **界面与服务器不一致时，先同 reducer 重放。** 把 `GET /api/runs/:id/events` 拉下来，在页面里用同一份 `reduceEvents`（[`ui/public/app.js`](../ui/public/app.js)）从初态重放。重放对、界面错 → 投递/控制器（隐藏页 rAF 不触发、误关 SSE、批处理饿死）。重放也错 → reducer：`reduceEvent` 是逐字段白名单投影，未列出的字段静默丢弃且不报错。

5. **并发是一等缺陷类，不是附加题。** 单测绿不能为真机开脱。优先查：后台标签页事件堆积、已终止仍显示「等待模型响应」、Windows 路径切不开、白名单字符串与 `resolve` 后的 workdir 不等、纯函数绿但控制器提前关连接。测窄屏必须用真实视口，强制元素宽度不会触发媒体查询。

6. **共享资源先隔离再加压。** 人设分 scratch；产品仓只读。停会拉起 node 的后台任务后，必须 `Listen` + CommandLine 双查；禁止对 PID 0 / 4 `taskkill`。Ollama 队列、共用输出目录、ST-Link 这类独占资源，本层软件切片根本不碰——碰到就停，不要假装测到了硬件。

7. **准入护栏是预期行为。** `maxActiveRuns` / 日预算 429 记「诚实拒绝」。日预算超限后新 run / 追问 / 归档派生 / 计划批准拒，在飞不掐。只有无文案、误伤在飞 run、或拒完 UI 卡死才是缺陷。

8. **弱模型测的是 harness 放大系数。** 全 flash（执行者 / 核查者 / planner 同档）与「核查者应 ≥ 执行者」的研究结论相反，是有意压弱。失败先按案例 #8 三层归因，顺序不能颠倒：规则挡住 → 预算掐断 → 缺手段。UI 必须让人能继续对话，而不是跟模型一起宕机。flash 写错、核查假阴性、计划拆不动，默认记模型/提示，除非 UI 卡死或 SSE 断了。

9. **证据三件套。** 每个发现：`runId` + 事件类型与序号 + 截图或 API 摘录。缺一件就还是转述。无 `runId` 的壳层问题用 URL hash + DOM 断言（或等价的可复核定位）。

10. **波次，不要蛮力并行。** 见上一节。协调者放行第二波，子代理不得自行加塞第 4 个模型 run。

11. **本轮不修只记账，除非 blocker。** 发现写入证据目录，按下一节分级。只有 P0 才允许热修产品代码，并回归「修复是否破坏其他人设的在飞对话」。评测本身不对产品仓 `git commit`。

## 可数事实（禁止「感觉还行」）

每条结论必须能指回一件可复核的东西。下面是本层常用判据，不是新 API。

| 声称 | 可数事实 |
|---|---|
| 同 run 可追问 | 同一 `runId`，`POST /api/runs/:id/messages` 200，时间线多一条 user |
| 会话中心化 | error / 停止 / 核查未过 / 计划跑完后仍能追加；唯一硬挡是谱系预算耗尽且提示点名 env |
| 计划未掐死 SSE | planner `done` 之后仍有 `plan_result` 或子任务事件 |
| 队列只跟事实走 | chip 随 `message_queued` 出现/消失，取消等服务端回执 |
| 第 5 个 run 被拒 | 429 + `Active run limit reached`；既有 4 个 `status=running` 不变 |
| 装配诚实 | 条上的模型/护栏/MCP 与 `/api/harness` 一致；「固定 N 轮」这类文案必须仍为真 |
| 终止徽章诚实 | `stopReason` 与徽章一致（事实源 `src/types.ts` `STOP_REASONS`）；`max_turns` 不得画成绿色完成 |

性能与配额只观察、不设 SLA：3 路并发时 TTFT、侧栏是否跟手、日账与各 run usage。数字记下来，不据此单独开缺陷，除非已经挡用。

## 严重度与模型 / harness 拆分

「挡正常使用」先归五类再套严重度。五类是观察清单，不是新接口。

1. **挡提交**：提交死、错误不可关、workdir 选不中、429 无解释。
2. **挡观看**：直播停、隐藏后永不更新、已终止仍显示「等待模型响应」。
3. **串台**：点 A 看到 B 的流 / 审批 / 队列；导演条进入错孩子。
4. **说谎**：装配条或文案与 `/api/harness` 不一致（例如写「固定 15 轮」而实际可配）。
5. **壳层挡主路径**：设置/搜索/记忆打开后盖住输入框或偷走焦点且回不来。

归因必须先拆模型与宿主。

**严重度（本层口径，不同于 docs/08 成熟度 P0/P1/P2 的产品优先级）**

| 级 | 含义 | 例 |
|---|---|---|
| **P0** | 挡用 | 提交按钮死、错误不可关、workdir 选不中、429 无解释、直播停且回不来、隐藏标签后界面永不再更新 |
| **P1** | 说谎或串台 | 点 A 看到 B 的流/审批/队列；导演条进入错孩子；装配条/文案与 `/api/harness` 不一致；`stopReason` 徽章撒谎 |
| **P2** | 观感 | 滚动不跟手、空态文案含糊、壳层打开后焦点别扭但回得来 |

P0 才允许热修。热修后必须确认其他人设的在飞对话仍在长，不能用「重启宿主」当验收。

**模型 vs harness**

- 记 **模型/提示**：flash 写错、核查假阴性、计划拆不动、工具选错但圈禁/审批按设计挡住。
- 记 **harness**：工具圈禁失效、审批门死锁或双响、`finish_task` 语义被绕过、队列不跟事件走、SSE 被客户端误关、reducer 丢字段、护栏 429 误伤在飞 run。
- 弱模型把 harness 缺口放大时，**缺口归 harness**，模型弱只是探针。三层归因用完之前，不要写「模型不行」。

硬件/EDA 入口本层只看装配诚实：未配 MCP、未选硬件包时，不得假装能烧录、能布板。连板与落板不在范围（见「明确不做」）。

## 证据三件套

每个写入证据目录的发现必须能同时指出：

1. **`runId`**（壳层无 run 则 URL hash）。
2. **事件类型 + 序号**（直播 `seq`，或 `events.jsonl` 行）。需要对照服务端时拉 `GET /api/runs/:id/events`，不要凭记忆复述。
3. **截图或 API 摘录**（429 正文、`/api/harness` 快照、DOM 断言原文）。摘录保持可核对，不改写成故事。

协调者综合报告（证据目录下的 `REPORT.md`，默认不入库）至少含：功能 × 人设 × 通过/降级/未测（附原因）；缺陷表（是否影响其他用户）；哪条纪律当场用上了；值得固化的 vitest / E2E 锁（只提名，本层默认不写测试）。

## 明确不做

- Electron 打包路径、Android、容器 canary（仍归 BASE-04 其余切片与 E2E-01/E2E-02）。
- STM32 烧录 / 真机 HIL、KiCad 落板。软件面只扫入口是否诚实。
- 改设置里的真实 key；把产品仓当任务目录；评测过程对产品仓 `git commit`。
- 为「试试上限」同时开第 5 个模型 run 挤掉别人。
- 把本层绿当成 BASE-04 整项关闭。BASE-04 要真实模型、浏览器、已安装 Electron、Android、容器 canary 与 STM32 HIL **同时**验收；本层只交软件切片证据。
- 现场发明新 API 或新护栏语义。只引用已有端点与已有字段；加字段必须同提交接宿主投影——那是产品改动，不是本文件的范围。
