## 分析：区分度研究弧线的收官之作

### 结果读法

- **scale-double 3/3**：flash 的脚本本能正面击破了不完备 oracle 陷阱——它没有依赖
  测试（9/60 覆盖），而是程序化枚举全部 60 文件批量重写，字节级零漂移。合理通过：
  会写正确的批处理脚本就配得上这个分。
- **scale-audit 2/3**：唯一失败是 **max_turns 耗尽**（15 轮烧完连产物都没写出），
  不是"只查直接依赖"的语义捷径（两次通过都给出精确的 19 项闭包）。
  区分轴再次落在【轮次预算 × 任务规模的张力】上——与 hard-import-list（t15 时
  0/2、真 bash 后 1/2）、rework 轮（t8 逼出返工）完全同源。

### 区分度研究总图（四套件 · 约 80 runs · 最终结论）

对 flash 级模型（配真 bash + rule-precedence 纪律后）：

| 区分轴 | 状态 |
|---|---|
| 语义陷阱（栅栏错/干扰计数/子路径） | 饱和（100%） |
| 字节纪律 | 饱和（write_file 直通 LF） |
| letter-vs-spirit 规则遵从 | **已被纪律条款解决**（7/10→10/10） |
| 变更+回归（快 oracle） | 饱和（编辑→测试→修复闭环拆弹） |
| 不完备 oracle | 饱和（脚本枚举绕开 oracle 依赖） |
| **轮次预算 × 规模张力** | **唯一存活的区分轴**（t15 下 67-83%） |
| 能力边界语义滑坡 | qwen 档存在，flash 档不可见——verifier 的主场 |

**harness A/B 的下一次实验应直接在"预算 × 规模"轴上做**（如 compact 策略、
子任务切分对预算张力的缓解），其余轴已无信号可采。
