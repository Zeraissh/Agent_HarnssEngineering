## 2. 一句话小事

把工作目录换成 `D:\Work\scratch\live-mu-20260914\lingma`（目录选择器先显示「正在加入白名单…」，过几秒才「已加入工作目录」。占位变成「要「lingma」做什么…」）。权限拧到「逐次审批」，关掉「自动放行」和「独立核查」。点「新建对话」，中文输入：

## 4. 稍长一点的事

新建对话。勾「计划」，权限选「计划确认门」。输入栏旁仍写着「独立核查（计划编排默认仍核查子任务）」——独立核查勾是关的。中文输入：

> 列一下这个目录有什么文件，再写一份只有三行的说明到 lingma-note.txt。先出计划等我改，不要直接写。

点「运行任务」。顶栏 `FATHOM · RUN C49212`。先 `Thinking...`，再出现「编排计划 / 2 步 · 层宽 1 · 并行度 1」，planner 自己先 `glob` / `read hello-lingma.txt`。大约半分钟后出卡：

> ◈ 计划待你签字
> 计明远（planner）已拆出 2 个子任务。下面是每一步要做什么——批准后才会发射第一个子任务；此刻否决没有任何副作用。
> 批准并开跑 / 否决（中止本次运行）

卡片正文是 s1「只读勘察并输出落盘前计划」+ s2「委托方批准后写入恰好三行…」，每步「验收 6 条」，里面有 `win32`、`Git Bash`、`UTF-8 且不带 BOM`、`换行 LF`、`python -c` 写文件示例。领域包名单还在输入栏上面。

认不认这些词：

- **计划**：认得「先出计划等我改」。这里变成「编排 / 子任务 / 验收 6 条 / 委托方」，不像 IDEA 里改两行注释的预览。
- **包**：名单 `stm32-debug` / `kicad` / `python-coding`。没有 Java / Go。不知道为什么列目录要选包。
- **核查**：没勾独立核查，条上仍说「计划编排默认仍核查子任务」。

| 判定 | 证据 | 我本来以为会…… |
|---|---|---|
| **好** | 勾了计划门之后，真的停在「计划待你签字」，有「批准并开跑 / 否决」。没有直接写 `lingma-note.txt`。 | 先给人看一眼再动手。 |
| **不习惯** | 一件列目录被拆成 planner 子任务、层宽、并行度、验收 6 条、python 写盘纪律。 | 通义里就是「先给方案再生成」，方案是人话几条，不是验收协议。 |
| **不实用** | 「领域包 / 计划编排 / 独立核查 / 计明远（planner）」同时出现。Java/Go 同事不会为了三行说明学这套黑话。会关计划，或直接关这个网页。 | 日常小事不要编排。 |
