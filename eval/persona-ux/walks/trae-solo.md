# Trae SOLO 惯用者 · 走查卡

- **角色：** Trae SOLO 惯用者（三栏任务台是家：左任务 / 中过程 / 右预览；先 Plan 再执行）
- **表面：** Web http://127.0.0.1:4173/ + 桌面对照
- **日期：** 2026-09-14
- **活 UI：** 是。`http://127.0.0.1:4173/` 当时 Listen；页标题「FATHOM 控制台」。走查在自己的 Chrome 里点完 1–6，桌面壳对照第 8 步。
- **习惯伸手：** 找三栏有没有就位 → 点「新任务」不是「新对话」→ 输入后期待 Plan → 改计划条目 → 视线往右找预览。

盯的迁移缝：三栏 / Plan 后执行 / 实时跟随 / 右侧预览。

## 1. 冷启动

打开 `http://127.0.0.1:4173/`。第一屏是两栏聊天台，不是三栏任务台。

**左栏**（侧栏约 312px）：品牌 `FATHOM.`；`Work` / `Code`（Code 亮着）；主按钮字是「新建对话」，不是「新任务」；搜索「搜索对话…」；下面按文件夹分组的旧对话标题（当时已有别人在跑的 `ui-qa` / `Agent_Design` 历史）。

**中栏**：大字

> AGENT CONSOLE
> FATHOM.
> see every run to the bottom.
> 每一层都看得见。

输入栏标签是「任务描述」，占位「要「ui-qa」做什么…」。旁边是项目「未入项（按目录）」、工作目录、模型「环境变量 · deepseek-v4-flash」、勾选「独立核查」。欢迎卡三张：「从计划开始 / 先对齐做法，再动代码」「看看这个仓库 / 用一段话说明项目在做什么」「修一处并跑通测试 / 改代码，用测试当判据」。

**右栏：没有。** 量过 `#center-row` 的孩子：`#main-area` 宽 1115；`#file-preview-overlay` 和 `#artifact-canvas-view` 都是 `display:none`、宽 0。右侧空的，没有预览窗、没有浏览器。

右下角盖着新手卡，四页原文：

1. 「初次使用 / 先圈定工作目录 / 工具写入圈是白名单里的全部目录。主目录是这次的焦点；其它已添加的项目也可以直接改，不必绕路。 / 1 / 4」
2. 「用一句话写下目标 / Enter 发送，Shift+Enter 换行。下面的例子只填进输入框，由你确认后再跑。 / 2 / 4」
3. 「运行设置按次装配 / 领域包、计划编排、独立核查都在「运行设置」里。没开的能力不会假装在。 / 3 / 4」
4. 「对话按项目分组 / 左侧是历史。点项目名可以收起一组；标题会尽量收成短句，而不是整段任务。 / 4 / 4 / 开始使用」

点完「开始使用」，overlay `display:none`。第一眼该找的「新任务 / Plan 草稿 / 右侧预览」一个都没就位。

| 判定 | 证据 | 我本来以为会…… |
|---|---|---|
| **不习惯** | 主按钮是「新建对话」。左侧是对话历史，不是任务卡。 | 点「新任务」，左侧是任务台。 |
| **不习惯** | 中栏是 Agent Console 欢迎语 + 一个「任务描述」输入框。没有计划草稿区。 | 一进来中间就是 Plan 条目，可以改再跑。 |
| **不习惯** | 右侧预览坞 `#artifact-canvas-view` 关掉，宽 0。视线往右是空的。 | 三栏就位：右栏已经开着预览或浏览器。 |

## 2. 一句话小事

欢迎态仍在。点「运行设置」先看了一眼：默认「计划」未勾（说明「拆解后等人批准」）；「多 agent」未勾；「自动放行」勾着；权限写「自动 · ask 级会自动放行；deny / 圈禁 / 硬拒仍拦住」。关上面板。

在 `#task-input` 写：

> 在当前工作目录写一个 hello-traesolo.txt，内容只有一行：ping。不要读别的文件，不要跑命令。

发送按钮读屏名「运行任务」。点下去立刻变成「停止」，宣告：

> 新任务已提交：在当前工作目录写一个 hello-traesolo.txt，内容只有一行：ping。不要读别的文件，不要跑命令。

中间栏出 `FATHOM · RUN 16DBB4`、用户原句、「等待模型响应…」「Thinking…」。**没有先出 Plan 草稿，也没有让我改条目。** 右侧预览坞仍是 `display:none`。

一两秒后宣告「运行已完成」。中间是一段叙述：

> 已在工作目录创建 hello-traesolo.txt，内容为单行 "ping"（5 字节，含行尾换行）。

同屏还有产物卡「hello-traesolo.txt / 文档 / 产物 / 预览 / 下载 / 在文件夹中显示 / 变更」，以及一句对着干的「本次运行没有写盘操作」。磁盘上该文件确实是 `ping`（5 字节）。发送钮改成「继续对话」。

右侧还是空的，直到我伸手去点产物卡上的「预览」。点完才三栏就位：左栏 312 / 中栏 691 / 右坞 `#artifact-canvas-view` 424，坞里原文 `ping`，标题 `hello-traesolo.txt`。

| 判定 | 证据 | 我本来以为会…… |
|---|---|---|
| **不习惯** | 默认自动放行，一句话直接写盘，没有 Plan 给我改。 | 先出计划草稿，我改完再执行。 |
| **不习惯** | 过程中间栏在动（Thinking / 等待模型），但右侧预览要事后点「预览」才开。 | 执行时右栏已经跟着出预览。 |
| **好** | 点了「预览」之后，右坞真的显示文件原文 `ping`，中栏没被盖掉。 | 三栏任务台：左任务 / 中过程 / 右预览。 |
| **不习惯** | 同屏「已创建 hello-traesolo.txt」和「本次运行没有写盘操作」对着干。 | 预览和状态说同一件事。 |

## 3. 要批准的事

第 2 步默认「自动放行」开着，写盘没问人。点「新建对话」，打开「运行设置」，把权限改成「逐次审批」（`permission-mode-select=manual`），把「自动放行」勾掉。说明行当时仍停在「自动 · ask 级会自动放行…」，旋钮和文案对不上。

再发：

> 在当前工作目录写一个 approve-traesolo.txt，内容只有一行：gate。不要读别的文件。

中间栏先是「等待模型响应… / Thinking…」，随后输入框上方钉出卡片原文：

> ⚠ write_file
> { "path": "approve-traesolo.txt", "content": "gate\n" }
> 允许本次
> 拒绝并说明

点「允许本次」后工具打勾，文件落盘内容是 `gate`。中途宣告闪过「连接中断，正在重连…」，横幅原文还有「（运行仍在服务端继续）」，随后「运行已完成」。

| 判定 | 证据 | 我本来以为会…… |
|---|---|---|
| **不习惯** | 挡下来的是工具名 + JSON，不是计划条目。按钮是「允许本次 / 拒绝并说明」。 | 先改 Plan 条目，再整段执行；不是逐个 `write_file`。 |
| **不习惯** | 默认自动放行时，第 2 步根本没有这张卡。要自己翻「运行设置」改「逐次审批」。 | 先 Plan 再执行是默认，不用我去翻隐藏旋钮。 |
| **好** | 卡钉在输入框上方，不跟着聊天滚走；「允许本次」之后文件确实是 `gate`。 | 批准位固定，批完能看见结果。 |
| **不实用** | 权限已选「逐次审批」，说明仍写「自动 · ask 级会自动放行」。 | 档位和一句话说明一致。 |

## 4. 稍长一点的事（开计划）

点「新建对话」，打开「运行设置」，勾上「计划」。说明变成「出图后等人批准。日常对话、小修请关掉」；权限值跟着变成 `plan`（计划确认门）。发：

> 列一下这个目录有什么文件，再写一份三行说明到 note-traesolo.md。先给出计划让我看，再执行。

中间栏先是「等待模型响应… / Thinking…」，**没有立刻出可改的计划条目**。先钉出一张提问卡，标题原文「◆ 施敢当 有 3 个问题需要你定」，第三问居然是「『先给出计划让我看，再执行』是否要求先停下来等你确认」。按钮「提交答复 / 都让它自己定」。我勾了三道「推荐」再提交。

之后中间栏出现「编排计划 · 2 步」，输入框上方才钉：

> ◈ 计划待你签字
> 计明远（planner）已拆出 2 个子任务。下面是每一步要做什么——批准后才会发射第一个子任务；此刻否决没有任何副作用。

s1「输出执行计划并停在确认点（不写任何文件）」；s2「列顶层清单并写入三行 note-traesolo.md」。正文很长，夹着 `REPORT-ONLY/UNISOLATED`、一串只读根路径。底部只有「批准并开跑 / 否决（中止本次运行）」。**没有编辑框，改不了条目。** 右侧预览仍是宽 0。

点「批准并开跑」后，并没有直接跑完。中间出现子代理条「输出执行计划并停在确认点（不写任何文件） / 工作中 · 需批准 / glob」，还有「允许本次 / 短期允许相同参数 / 拒绝并说明」。坞上一条「子代理待批准：…」。实时跟随有：Thinking、工具名打勾/打叉、编排计划展开。右栏还是空的。

| 判定 | 证据 | 我本来以为会…… |
|---|---|---|
| **好** | 勾了「计划」之后，真有「◈ 计划待你签字」和 s1 / s2，批准前不发射。 | 先 Plan 再执行。 |
| **不习惯** | Plan 默认关着，要进「运行设置」才勾得上；勾上之前先被三道问答题拦一次。 | 一句话进任务，立刻看到计划草稿。 |
| **不习惯** | 计划卡不能改条目，只能整份「批准并开跑」或「否决」。 | 改计划条目，再跑。 |
| **不习惯** | 签完计划还要批子代理的 `glob`。 | 实时跟随过程，但不点每一个工具调用。 |
| **不实用** | 计划正文是只读根清单和验收 6 条，不是我能扫一眼的任务卡。 | 中间栏是短条目，右边已经在预览。 |

## 5. 过程中途

计划跑到子代理还在要批准时，发送钮仍是「停止」。点下去。中间栏收成：

> 已停止 · 这次运行由你主动停止；已完成的工具调用与写入不会回滚。

还写「1 个子任务未执行」（s2 没跑）。读屏宣告却是「运行已完成：…」。发送钮变成「继续对话」。

左侧列表能点回「在当前工作目录写一个 hello-traeso…」，中间还是 `FATHOM · RUN 16DBB4`，产物卡「hello-traesolo.txt / 文档 / 预览 / 下载」，发送钮「继续对话」，占位「接着说…」。点底栏「打开指挥中心」换成另一套三栏：

> 指挥中心
> 1 运行中 / 0 待决定 / 41 今日完成
> 待你决定 / 运行中 / 最近完成

我停掉的那次在「最近完成」标「被停止 · 1 分钟前 · 耗时 2 分钟」。这是任务看板，但不是左任务/中过程/右预览。

刷新页面后，地址变成 `#/run/16dbb47f-…/loop`，同一场 RUN 16DBB4 还在，侧栏「hello-traeso…」还在，发送钮仍是「继续对话」。

| 判定 | 证据 | 我本来以为会…… |
|---|---|---|
| **好** | 「停止」立刻停，文案写清「由你主动停止；已完成的…不会回滚」。指挥中心把这次标成「被停止」。 | 中途能打断，回来能从任务卡接着。 |
| **好** | 刷新后还在原来的 run，不是空白欢迎页。 | 回来不用考古聊天记录。 |
| **不习惯** | 宣告说「运行已完成」，和「已停止 / 被停止」对着干。 | 停就是停，不要写成完成。 |
| **不习惯** | 点回旧任务时右侧预览又关上了，要再点一次「预览」。 | 任务卡打开就带右预览。 |
| **不实用** | 指挥中心的三栏是待决定/运行中/最近完成，要先点底栏图标才看得到。 | 打开就是三栏任务台。 |

## 6. 换地方

点「新建对话」，打开工作目录菜单，原文：

> 勾选的目录本次都可以读写。设为主只换默认写入点，不会把旧主目录自动勾回。

列表里有 `Agent_Design`、`ui-qa`、`liquid-demo`、`AGS`、`live-mu-20260914\chat` 等，还有「＋ 添加目录…」。项目下拉是「未入项（按目录） / 网盘管理 / T5-live-mu-chat / ＋ 新建项目…」。

把主目录改成 `…\live-mu-20260914\chat` 后，占位变成「要「chat」做什么…」。再把项目改成「T5-live-mu-chat」，左侧历史只剩那一组（八十个短句、支线落地笔记…），`hello-traesolo` 从当前列表消失——它还在 `ui-qa` 那一组里。走查后把主目录改回 `ui-qa`（触发器一度写成 `ui-qa · +1`，chat 仍勾着）。

| 判定 | 证据 | 我本来以为会…… |
|---|---|---|
| **好** | 换目录后面占位跟着改「要「chat」做什么…」；换项目会收侧栏。 | 换一个工作台，任务列表跟着换。 |
